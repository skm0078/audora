# Zipped books with non-Unicode names, and comics with a bad or huge page, open instead of crashing (2026-10-29, no ADR)
- Edge-case pass, gap E1. Windows' built-in zip and older tools store names in the PC's code page with the UTF-8
  flag clear; many manga CBZs and EPUBs with Indic picture names are made that way. Java's zip readers throw
  IllegalArgumentException (ZipException on the desktop JDK's ZipFile) at the first such name. Nothing caught it:
  the reader crashed the app (its screen scope), Play failed with no message (the service only logged it), and a
  CBZ crashed the app while its photo book was made (PhotoBooks' scope has no handler).
- New `playback/text/ZipNames`: reads names as UTF-8 first, then again from the start with Latin-1, which maps every
  byte, so ASCII names still match the book's own references. Used by TextBooks (EPUB, Word, OpenDocument, zipped
  FB2), FileDetailsReader and ComicBookFile (which keeps the charset that read the page names, so it finds them
  again). TextBooks.open, FileDetailsReader.read and the comic maker also report any other IllegalArgumentException as a
  damaged file instead of crashing.
- Gaps E2 and E3: a comic page was read whole into memory with no limit, so one huge page (or a zip that unpacks to
  far more than its size) ran the phone out of memory, an Error the photo maker's guard does not catch; and one page
  Android could not decode failed the whole comic. Now each page is capped at `PhotoConfig.maxComicPageBytes`
  (64 MB; the zip's claimed size is checked first, the bytes read after), and a page that cannot be read, decoded or
  held in memory becomes a blank page the size of the one before (`PhotoBookFile.writeKeepingBadPages`), so the page
  numbers still match. A comic with no page that draws is still refused as unreadable.
- Perf cost: none for UTF-8 zips (read once, as before). A code-page zip is read twice, once, when it is opened.
- "What's new" entry: `app/src/main/assets/whatsnew/2026-10-29-zip-names.txt`. `:pdf` unchanged. No new dependency.
- **Could affect:** opening EPUB, Word, OpenDocument and zipped FB2 books; book details and covers filled in when
  added; comic archives made into photo books.
- **Verified in CI:** `ComicBookFileTest` on the emulator (a damaged and an oversize page left blank with the rest
  kept, only-broken pages refused, non-UTF-8 page names read and found again); `ZipNamesTest` (code-page stream and file read with Latin-1, an EPUB with a code-page picture
  name still parses, UTF-8 zips read once with their names, a damaged zip still fails as damaged); release journey
  step 54 opens an EPUB and a CBZ written by `scripts/fixtures/make_zip_name_fixtures.py`.

**Real-device checks (the test phone):** put a few pictures with non-English names (for example `página1.jpg`) in a
folder on a Windows PC, use "Send to > Compressed (zipped) folder", rename the zip to `.cbz`, copy it to the phone and
open it with ListenLock: it becomes a photo book. A comic with one damaged picture opens with that page blank. Ordinary EPUBs and comics open as before.
