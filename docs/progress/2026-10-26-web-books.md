# Web pages and free book catalogues (2026-10-26, ADR 2026-10-26-web-books)
- **Read a web page** (Library ⋮): type or paste an address; ListenLock downloads that page once and reads its
  article (Readability4J) as a text book, without menus, ads or footers. A link shared from a browser or chat now asks
  "Read this web page?" with the site's name, instead of "share the text instead". A link straight to a PDF or EPUB
  adds that book.
- **Free book catalogues** (Library ⋮): Project Gutenberg built in, any https OPDS catalogue can be added. Sections,
  search, More, and Download on books in a format ListenLock reads (EPUB first). The book is added and opened.
- Only on a tap, HTTPS only, nothing about the listener sent, size-capped, one download at a time with Cancel.
- Privacy policy, in-app privacy statement and README updated. New libraries: Readability4J, jsoup, SLF4J API.
- "What's new" entry: `2026-10-26-web-books`. No `:pdf` change, PIPELINE_VERSION unchanged.
- **Could affect:** sharing a link or text to ListenLock (the shared-text path), the library ⋮ menu, Voices &
  licences, the release build (R8 with the new libraries).
- **Verified in CI:** `WebAddressTest`, `WebArticleExtractorTest`, `OpdsParserTest`, `WebBooksTest` (unit),
  `WebBooksScreenTest` (device: the menu entries open their dialogs, the address check, a shared link asks first),
  `ReleaseJourneyTest`.

**Real-device checks (the test phone, with internet):**
1. Library ⋮ > Read a web page > paste a news article's address > Read: a progress dialog names the site, then the
   article opens as a book and plays; the menus and footer are not read.
2. In Chrome, Share a page > ListenLock: "Read this web page?" names the site; Read opens the article.
3. Library ⋮ > Free book catalogues > Project Gutenberg > search "Pride and Prejudice" > open the book > Download:
   it is added and opens; play reads chapter 1. Cancel during a download leaves nothing in the library.
4. Turn on aeroplane mode and repeat 1: "Could not reach the site", nothing added.
