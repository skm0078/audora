## P3-01 — Script routing per sentence (2026-10-16)
- **A mixed sentence switches voice mid-sentence:** each script run is read by its language's voice, the one picked in Settings → Voices (P4-01) or the default. Rules (ADR-026): Latin → English, Devanagari → Hindi, Bengali → Bengali; punctuation and ASCII digits stay with the run before them; inside a mostly Hindi or Bengali sentence fewer than 3 English words ("PDF", "Article 12") stay with the Indic voice (`ScriptRoutingConfig.minEnglishWordsInIndic`); Indic words inside English always switch.
- **How:** `speech.route.ScriptRouter` (pure Kotlin) cuts the sentence; `RoutedSpeech` renders the parts and joins them into one clip at the highest sample rate (new `PcmAudio.resampled`, linear, up only); `EngineRenderer` uses it, so playback, highlight and resume still work per sentence. `ReadingUnit` and `:pdf` output are unchanged: no `PIPELINE_VERSION` bump, golden score unchanged. The script-to-language map moved to `:core` (`ScriptLang`), shared with `:pdf`'s `ScriptDetector` (same output).
- **No Hindi voice on the phone:** a Hindi word inside an English sentence no longer fails the sentence; it is read whole by the English voice as before, with a warning in the log (page, sentence, reason).
- **Done-when:** `MixedScriptVoicesTest` (device, CI emulator) reads the bilingual UDHR PDF (`enhi-udhr-bilingual.pdf`) through the real pipeline and renderer with recording voices: the English voice never gets Devanagari, the Hindi voice never gets three English words in a row, every sentence's parts add up to the sentence, mixed clips come out at the higher rate, and voices switch 100+ times. On the desktop dump of the same PDF: 186 sentences, 4 mixed (e.g. "…the rule of law, चूंकि मानव परिवार…"), 129 switches; before P3-01 those 4 were read by one voice.
- Tests: 13 new JVM tests (router table with real UDHR sentences, threshold, parts add up; RoutedSpeech joining, rates, fallback, failure; resampling). ktlint/detekt run in CI (no Android build in this workspace); the JVM tests ran locally in a harness.

## P3-05 — OCR for scanned pages with Tesseract (2026-10-16)
- **Scanned pages are read aloud.** Pages P3-03/P3-04 route to OCR (no text layer, a scanner's hidden layer, broken glyph maps, junk, impossible Indic sequences, unknown legacy glyphs, a failed book sample) are now drawn by PDFium at 300 dpi in greyscale and read by Tesseract 5.5.1 (Tesseract4Android 4.9.0) with the `tessdata_best` English, Hindi and Bengali models. The text gets the same repair and sentence split as a text layer (line-end hyphens, junk, NFC); lone page numbers are dropped. P3-03's Hindi/Bengali book sample now really runs, so office exports with wrong conjunct maps switch to OCR.
- **Languages are found automatically:** a broken page uses its own letters; a scan uses the languages the book has already shown; the first page of a scanned book gets one quick 100 dpi probe with all three models.
- **Models download once, as one pack (≈ 38 MB):** Settings → "Scanned pages (OCR)" (Download / Cancel / Delete with progress), or the card the reader shows on a scanned page. Same resumable, SHA-256-checked background download as voices (P4-01); the files come from the upstream tessdata_best repository at a fixed commit, pinned by SHA-256 and size. Until they are downloaded the page reads its text layer (often nothing) and the reader says why.
- **Badge:** the reader marks OCR'd pages "OCR — read from the page image; a few words may be wrong".
- **Speed:** each page is OCR'd once per book and cached on disk (16 MiB, oldest pages dropped first), shared by the reader and the player. Every recognised page logs `renderMs`, `recognizeMs` and the character count (no text): this is the per-page time for the phone check.
- ADR-025 (engine from JitPack with the AAR's SHA-256 checked before every build, models pinned at an upstream commit instead of a mirror, one pack, cache, probe; PaddleOCR experiment not built because Tesseract's Hindi error rate is already under the 5 % bar). `PIPELINE_VERSION` = 6. New dependency: Tesseract4Android (already in the AGENTS.md stack).

## P4-01 — Voice manager (2026-10-16)
- **Settings → Voices** lists every voice by language: the built-in English voice, the catalog voices to download (size and licence shown), voices already downloaded or imported, and for Hindi/Bengali "Phone's voice" (the default). The radio button picks which voice reads that language; the choice is saved and used by the player from the next sentence. Downloaded and imported voices can be deleted (asks first); a deleted voice stops being the choice.
- **Downloads** run in the background (WorkManager, needs a network connection, retried with backoff, up to 8 tries) and show progress on the row; Cancel stops and throws away the partial file. **An interrupted download resumes** from the bytes already received (HTTP Range), so closing the app, losing the network or Android stopping the job only pauses it. **A corrupt file is rejected:** the whole zip is checked against its SHA-256 pin and deleted on mismatch; a server sending more bytes than pinned is cut off. Free space is checked first (zip plus unpacked copy plus 50 MiB). Installs swap in atomically, so a killed install never leaves a half voice.
- **Catalog** (`speech/models.json`): Piper en_US cori (64.6 MB) and KittenTTS nano (28.8 MB) for now. Their zips are our own reproducible repacks of sherpa-onnx's releases (no bzip2 on Android), built and verified by the new `voice-mirror` workflow and uploaded to this repo's `voices` pre-release from `dev` only, never replaced. The build validates `models.json` and packs it into the APK, so pins come with the signed app.
- **Import:** "Import a voice" takes a sherpa-onnx Piper/MMS (VITS) or KittenTTS folder, asks its language and a name, and copies only the files it needs. Folders it cannot read are refused with a reason (no model, several models, lexicon voices such as Kokoro, Kitten without espeak-ng-data, too big, too many files, no space).
- **Engine:** the sherpa engine now reads its voice list live (bundled + installed) and loads installed voices from files; a voice updated on disk is reloaded. Playback picks the voice per language: `SET_VOICE` override, then the Settings choice, then the default.
- ADR-022 records the mirror, the build-time catalog, the resumable worker and the import rules. No new libraries (WorkManager was already in the stack; first use). WorkManager adds `ACCESS_NETWORK_STATE`, `WAKE_LOCK`, `RECEIVE_BOOT_COMPLETED` and its boot receiver, which only reschedules downloads, never playback. `:speech` declares `INTERNET`.
- Tests: JVM tests for the downloader (resume after a drop, resume after a stop, server ignoring Range, corrupt file, file changed between runs, oversize, stale partial, complete partial, HTTP errors, no space), archive install (zip-slip, missing model, not a zip, size cap, update swap), on-disk layout and recovery after a kill, import rules, catalog parsing, the worker's retry rules, the Voices list and choices, the engine's live voice list, and the Voices screen controller. Python tests for the mirror script.

**Known limits:** downloads only work once this is merged to `dev` and the `voice-mirror` workflow has published the `voices` release. Hindi/Bengali catalog voices come with P3-06; until then Hindi/Bengali neural voices come only from import.

## P3-04 — Legacy-font converter: Kruti Dev, DevLys, Chanakya, Bijoy (2026-10-16)
- **Legacy-font Hindi and Bengali is read as words** (`pdf.legacy`, Build Spec §5 step 3a): text in Kruti Dev 010 (and Kundli, MINNO-GOPI), DevLys, Chanakya and Bijoy/SutonnyMJ fonts, which PDFium extracts as Latin gibberish ("izsl foKfIr"), is converted to Unicode ("प्रेस विज्ञप्ति") by table, chosen by font name (`QualityConfig.legacyFonts`). Pre-base signs and rephs move to their logical place, signs typed out of order are put in Unicode order, PDFium's spaces inside a syllable go, split vowels compose, "पी0एस0" → "पी॰एस॰". Runs wherever legacy text is read, before P3-03's Indic repair; offsets stay mapped (ADR-018).
- **Unknown glyphs route to OCR:** a page whose legacy runs hold ≥ 20 % of its letters with > 2 % codes no table covers (or in Shusha, which has no table) → OCR (`LEGACY_UNKNOWN_GLYPHS`), checked before the other signals; the rest are measured on the converted text. Bengali অ্য/এ্য is no longer counted as an impossible sequence.
- **Golden score: corpus 0.9187 → 0.9268** (two new generated documents, UDHR Hindi in Kruti Dev codes 0.9989 and Bengali in Bijoy codes 1.0000, `scripts/pdf/legacy_golden.py`; no other document moves). ADR-023, `PIPELINE_VERSION` = 5.
- Tests: 8 table-driven converter tests on phrases from the real files (Kruti Dev, DevLys, Chanakya, Bijoy, out-of-order signs, a word split across two fonts, pass-through and offsets, unknown codes), scorer tests for unknown-glyph routing and Bengali a-phala, and a golden routing test (legacy documents → converter; with every font unsupported → OCR). ktlint and detekt clean locally.

## P3-03 — Hindi and Bengali text quality: scorer, Indic reorder, OCR sample (2026-10-16)
- **Every page is scored and routed** (`pdf.quality.PageQualityScorer`, Build Spec §5 step 2): almost no letters (a scan), a mostly invisible text layer, Unicode-map errors > 2 %, junk > 2 % (U+FFFD, private-use glyphs, ASCII glued inside an Indic word) or > 1 % of Indic characters in impossible positions → **OCR**; KrutiDev/DevLys/Chanakya/SutonnyMJ/Bijoy runs → **legacy-font converter**; else **text layer**. Tunables in `QualityConfig` (`:core`).
- **Indic repair and reorder** (`IndicReorder`, step 3b), per paragraph before P2-03's repair, offsets still mapped (ADR-018): placeholder glyphs inside a cluster dropped on every page; on pages detected as visual order (pre-base signs ि ি ে ৈ starting words), pre-base signs moved after their consonant cluster, ে + া → ো and ে + ৗ → ৌ composed, rephs moved before their syllable. A page with too few signs to tell follows its neighbours.
- **Per-book OCR sample** (`TextLayerCheck`, ADR-011 §3): the first Indic page with enough text is OCR'd and compared with its repaired text layer line by line (CER ≤ 5 % → trusted, else every Indic page → OCR; re-check 1 page in 50). The OCR itself is P3-05: until then books are "unverified" and read their text layer. `PdfBook.readPage(page, builder)` returns the units with the page's route; `PdfBook.open(..., ocr = ...)` takes the OCR. Routes are logged with their measurements, never text.
- **Golden score: corpus 0.9051 → 0.9187.** The visual-order HUD Hindi fact sheet +0.06 ("हाउसिंग", "मानसिक") and HUD Bengali guide +0.19 ("বোঝা", "পূর্ণ", "মার্কিন"); no other document moves. ADR-021, `PIPELINE_VERSION` = 4 (resume re-anchors once by fingerprint).

## P2-03 — Headers, footers, page numbers, tables and text repair (2026-10-15)
- **Clutter is no longer read:** running headers and footers (a line in the top or bottom 8 % of the text area that repeats on 3+ pages of a 7-page window, or carries a page number that runs with the page: "CHAPTER 5. CONNECTIVES 33", "Page 3 of 50"), standalone page numbers (also Devanagari and Bengali digits), table interiors (runs of aligned, widely spaced cells and the columns paired with them; captions stay), bullet glyphs at line starts and bracketed citation markers ("[4–7]"; `CleanupConfig.skipCitationMarkers`, on by default as the spec says).

Every repaired character still maps to its glyph box (ADR-018 unchanged).

New `pdf.cleanup` (`ClutterRemover`, `MarginClutter`, `TableFinder`, `Folios`, `TextRepair`), tunables in `CleanupConfig` (`:core`). ADR-020. `PIPELINE_VERSION` = 3.

## P2-02 — Layout and reading order (2026-10-15)
- **Two-column pages are read in order:** `:pdf` now rebuilds each page's layout before cutting sentences (`pdf.layout`): glyphs are grouped into runs, a recursive XY-cut finds columns first (a full-width title or abstract is read before the columns under it), stacked pieces of one column are joined, then lines, paragraphs (line spacing, first-line indent, style change) and headings (≥ 1.15× the body size or a bold font name; font weight is not used, ADR-011). A sentence that runs from the bottom of one column into the next is one sentence. Tunables in `LayoutConfig` (`:core`).
- **Headings stand alone:** sentences are split within each paragraph, so "1. Introduction" is no longer glued to the first sentence below it. Heading and paragraph-end pauses are wired (`ReadingUnitConfig.headingPauseMs` / `paragraphPauseMs`) but stay 0 until P2-04 tunes prosody.
- **`charStart` now indexes the page's reading-order text** (`ReadingText`), not PDFium's extraction order (ADR-018); units stay ascending and contiguous, so the reader, the playback service and resume work unchanged. `PIPELINE_VERSION` = 2: positions saved by earlier builds re-anchor once by fingerprint (ADR-015). `PdfBook.readingUnits(page, builder)` is unchanged.
- **Safe fallbacks:** pages with few glyph boxes (OCR'd, converted) or vertical text keep extraction order; PDFium's line-end hyphen marks keep hyphenated words whole; PDFs that set 1 pt fonts and scale them (Elsevier) are sized by glyph height.
- **For P2-03:** `PageLayout` → `TextBlock` → `Paragraph` (`kind`, `continuesPrevious`) → `TextLine` (spans, box, size, bold) is public; header/footer removal drops lines and rebuilds the text with `ReadingTextBuilder` (pipeline 3).
- Tests: 23 new JVM tests. Synthetic pages: columns drawn row by row, PDFium joining two columns into one line, a title over two columns, sentences crossing the gutter, headings by size and by bold name, paragraph gaps and indents, a wide justified space on one line, an Indic vowel sign drawn left of its consonant, boxless pages, line-end hyphens. Real-page fixtures (`pdf/src/test/resources/layout/`, CC BY or public domain): the KJV two-column page matches its ground truth exactly; on a CC BY Elsevier paper the abstract, left and right columns come in order and gutter-crossing sentences are whole; the forallx textbook finds "2.3 Formal validity" as the only heading; English, Hindi and Bengali UDHR pages keep their text and order; no fixture loses or duplicates a character. A Hindi device test now expects the English corpus banner as an English unit of its own (it used to be glued to a Hindi sentence).

## P2-04 (part 1) — English normalizer (2026-10-15)
- **`EnglishNormalizer`** (`:speech`, `speech.normalize`): turns written English into what a voice should say, before every engine (ADR-012). Ten ordered rules, specific to general: links and e-mail addresses → "link"; money (₹/Rs./INR in lakh and crore, $, £, €, paise/cents, "₹5 crore", "$2.5 million"); clock times (10:30, 9 a.m. → "nine ay em"); abbreviations (Dr., Smt., e.g., etc., "Fig. 3", "pp. 10–12"; St. is Saint before a name, else Street); dates (15 August 1947, Aug. 15, 1947, 15/08/1947 day-first, ISO); minus signs; symbols (&, #5, 3 × 4, ±, ~); percent and units (km, kg, °C, GB, km/h…, with ranges); Roman numerals only where they cannot be words (after Chapter/Part/Class/World War, regnal names, "(iv)" labels, the start of a heading); then sections (3.2.1), ranges, phone-style codes, decades, ordinals, years and plain numbers. A bare four-digit number from 1100 to 2099 reads as a year.
- **Runs at render time, not on `ReadingUnit.text`** (ADR-019): the reader keeps showing the page's text and resume fingerprints never change when the normalizer improves. `TextRole` (BODY/HEADING) is the seam for headings from P2-02. Tunables in `NormalizerConfig` (`:core`): date order, link word, digit-by-digit cut-off, rupees in lakh/crore, year range.
- Tests: 183 table-driven sentence cases plus number-word tables (cardinals in both systems, ordinals, years), idempotence (normalizing twice equals once), config variants, and no digit left in long mixed text.
- **Not yet audible:** the playback renderer does not call it yet. Part 2 wires it into `EngineRenderer` and adds the prosody pauses (headings ~600 ms, paragraphs ~400 ms, list items) once P1-06 is on dev; heading pauses and heading numerals need P2-02.

**Real-device checks (after part 2, Moto Edge 50 Fusion):** play a page with a date, a ₹ amount in lakh, a URL and "Dr." and listen that each is read in words ("fifteenth August nineteen forty-seven", "one lakh fifty thousand rupees", "link", "Doctor").

## P1-06 — Exact resume and battery onboarding (2026-10-15)
- **Audora remembers the sentence:** while reading, the playback service saves the current sentence of each book as a `ResumeAnchor` (page, sentence start, head and tail fingerprints, pipeline version) in a new `resume_anchors` table (database version 2, Room auto-migration, one row per book, deleted with the book). At most one write per 2 s, and at once on pause, stop, sleep timer and end of book, so a kill resumes at most one sentence early.
- **Re-anchoring survives pipeline changes:** if `PIPELINE_VERSION` or the sentence split changed, the saved sentence is found again by its fingerprints before falling back to the offset and then the top of the page (ADR-015). Every resume logs which rule matched.
- **Where resume shows up:** opening a book that is not playing shows the saved page, and Play starts at the saved sentence. The "Reading stopped unexpectedly" prompt's Resume now opens that book and starts reading (replaces `TODO(P1-06)` in `DiagnosticsController` and `ReaderModel`). A headset play button with Audora closed resumes the last book (Media3 playback resumption). Reading still starts only from a user action; no boot start.
- **Battery onboarding:** the library shows a "Keep reading with the screen off" card until the app is exempt from battery optimization or the user says "Not now"; Settings has a Battery row that opens the same screen. It asks Android for the exemption (system dialog), opens App info, and lists the maker's own steps for Motorola, OnePlus, Samsung, Xiaomi, OPPO, realme, vivo, or a generic list.
- **Verified in CI:** core unit tests for fingerprints (pinned value), re-anchoring (pipeline version bump, split change, header glued on), the recorder's throttling and the write race the emulator test caught; reader tests for opening at the saved sentence and auto-resume; emulator tests for the Room store, the 1 → 2 migration, and a kill mid-sentence followed by a resume on a bumped pipeline version.

**Real-device checks (Moto Edge 50 Fusion, dev build; batch with the S1/S3 phone run):** (1) Read a few pages, App info → Force stop mid-sentence, reopen Audora and the book: it opens on that page; Play resumes at that sentence. (2) Force stop while reading, reopen: the "Reading stopped unexpectedly" prompt's Resume starts reading at that sentence. (3) Swipe Audora away while paused, then press a headset or Bluetooth play button: the last book resumes. (4) The battery card on the library, "Allow" shows the system dialog, the card goes away; Settings → Battery shows the Motorola steps and App info opens. (5) Remove a book and add it again: it starts at page 1. OnePlus 12 at the pre-release check: the OnePlus steps and (1).

## P1-04 — Playback service (2026-10-15)
- **Reading aloud works end to end:** the reader's Play / tap-a-sentence sends `PLAY_FROM` to `AudoraPlaybackService` (Media3 `MediaSessionService`, foreground type `mediaPlayback`), which opens the book through the library's file grant, extracts pages on one background thread (PDFium, P1-02) about a page ahead of the playhead, and reads sentence by sentence. Notification, lock screen, headset and Bluetooth buttons come from Media3's session (play/pause, previous/next sentence). Speed is the player's own (Sonic, C6).
- **Never ENDED while text remains (C5):** each playlist item is one sentence (a WAV served by `TtsDataSource`, which blocks until the render queue has it), and the playlist always ends with a "more is coming" placeholder that blocks until the next page is appended; only after the last page is it removed, so ENDED means the book is finished.
- **Render queue** (`RenderAheadQueue`): one worker thread renders the playing sentence plus 3 ahead (`QueueConfig.prefetchUnits`) with P1-03's `SpeechEngine`; a sentence that leaves the window mid-render is cancelled. Played sentences stay in an 8 MiB in-memory cache so skip-back is instant. Deviation from Build Spec §6 (20 MB disk LRU), recorded as ADR-016: memory only, because a disk cache of a user's book audio is one more thing to clean up and gains little for a sentence-level skip-back; revisit if skip-back of more than ~3 min is wanted.
- **Seek and voice change rebuild the queue:** every start, seek or `SET_VOICE` opens a new render epoch (new queue, new media ids `audora://book/<id>/e/<epoch>/…`); loads from an older epoch fail fast and are never played. A voice change restarts the current sentence in the new voice. English uses the bundled Piper voice by default, Hindi/Bengali the phone's best offline system voice (P1-03).
- **Recovery** (`PlaybackRecovery`): a sentence the engine cannot render is skipped (reported in the session extras), but 3 in a row stop reading with an error instead of skipping a whole book; a dead engine stops at once. Media3's stuck-buffering error (10 min, S3 finding 3) restarts the render queue at the current sentence, a second time on the same sentence skips it; "stuck" while Android suppresses audio (a phone call) just retries. Other player errors retry once.
- **Sleep timer runs in the service:** minutes (counted on `elapsedRealtime`, so deep sleep counts; when it runs out the sentence playing is finished first) or end of page (the player's pause-at-end-of-item).
- **Contract for the UI** (`playback.contract.PlaybackContract`): custom commands `PLAY_FROM`, `SET_VOICE`, `SET_SLEEP_TIMER` (only accepted from Audora's own package), each sentence's book/page/char range in its metadata extras, book/sleep timer/error in the session extras. The reader's `NoPlaybackPort` stand-in is replaced by `MediaControllerPlaybackPort`.
- **P1-07 hooks:** `onPlaybackActive(book, page)` while playing or buffering to play (and on every page change), `onPlaybackInactive()` on pause, stop, error, end and sleep timer; on a background thread.
- **Starts as soon as a sentence is rendered** (`QueueConfig.playbackStartBufferMs = 0`): with Media3's default start buffer (1 s, 2 s after a rebuffer) a run of short sentences never fills it, because the next sentence only renders once the playhead moves, so the player waited in BUFFERING forever. The emulator test found this.
- Wake lock: Media3's `WAKE_MODE_LOCAL` (S3 finding 4), no wake lock of our own. No boot start and no playback resumption from the system (P1-06). `<queries>` for the TTS service intent declared (Build Spec §6; P1-03 needs it to list system voices on Android 11+).
- Tests: JVM tests for the render queue (order, window, cancel, failure, recent cache, close), playlist feeding (placeholder swap, insert before placeholder, finish, trim behind), recovery rules, sleep timer, media ids, page cursor and WAV encoding. Device test (emulator job): the session on a real ExoPlayer with a fake book and voice reads every sentence in order and ends only after the last, starts at a char offset, rebuilds on a voice change, and skips a sentence that fails to render. No new dependencies.

**Known limits:** a 15- or 60-minute screen-off run can only be checked on a phone (below). Logs carry book ids, pages and sentence keys (`p12u3`), never the text.

**Real-device checks (Moto Edge 50 Fusion, dev build; batch with the S1/S3 phone run):** (1) Open an English PDF, press Play: reading starts within a few seconds and the notification shows the title and "Page N of M". (2) Screen off, phone on the table, 15 min (P1-04 done-when), then 60 min (Phase 1 done-when): reading never stops; Share logs afterwards. (3) Lock screen and notification play/pause/next/previous; wired or Bluetooth headset button pauses and resumes; unplugging the headset pauses. (4) Take a phone call while reading: it pauses and resumes after. (5) Go to page 20 while reading: reading jumps there. (6) Sleep timer 15 min with the screen off: stops at the end of a sentence. (7) A Hindi PDF with the phone's Hindi voice installed reads in Hindi; without it, the reader shows the error instead of silence. (8) Swipe Audora away from recents while paused: the notification goes away; while playing: reading goes on.

## P1-03 — Speech engines (2026-10-15)
- **`SpeechEngine` contract** (`:speech`): `render(text, voice)` returns 16-bit mono PCM or a typed `SpeechError` (`VoiceUnavailable` with reason UNKNOWN_VOICE / NOT_INSTALLED / NETWORK_ONLY / MODEL_FILES_MISSING, `EngineUnavailable`, `SynthesisFailed`), each with a readable message. Renders are main-safe, serialized per engine and cancellable (the caller gets `CancellationException`, the engine stays usable). `VoiceId`/`EngineId` and `SpeechConfig` live in `:core` so resume anchors can store a voice.
- **Bundled neural voice** (`SherpaSpeechEngine`): sherpa-onnx 1.13.8, 2 threads, one model loaded at a time, loaded on first render. Cancellation stops between sherpa-onnx's internal sentences. Release never frees a model under a running render. The voice is chosen in `speech/bundled-voices.json` (provisional: Piper ljspeech; swap to cori or Kitten by changing one line after the phone rating) and downloaded at build time from sherpa-onnx's release with a SHA-256 check; espeak-ng-data trimmed to en/hi/bn (ADR-014).
- **Phone's own TTS** (`SystemSpeechEngine`): `synthesizeToFile` into the cache, chunked by `getMaxSpeechInputLength()` at sentence/clause/space boundaries; only offline, installed voices; `bestVoice(lang)` says NOT_INSTALLED or NETWORK_ONLY per language when the voice pack is missing. Entry points: `SpeechEngines.bundled(context)` and `SpeechEngines.system(context)`.
- Tests: 44 JVM tests (chunker table, WAV reader, PCM conversion, manifest parsing, asset install incl. a killed copy, both engines over fakes: voice choice, missing packs, chunk join, sample-rate mismatch, errors, cancellation, release during a render). Device tests (emulator job, `:speech:connectedDebugAndroidTest`): the bundled voice renders real speech from the APK, a cancelled render leaves it usable, the system engine renders or reports a typed reason. Build task checked locally: Piper and Kitten unpack and speak in desktop sherpa-onnx; a wrong pin fails the build.
- APK grows by ~92 MB (model, espeak data, sherpa-onnx native libraries). No new libraries.

**Real-device checks (batched into the overnight run, Moto Edge 50 Fusion):** covered by P1-04's playback run: the first sentence starts within ~2 s of Play on a fresh install (model load + espeak copy), and a Hindi book with no Hindi voice pack installed shows the "download it in Text-to-speech output" message.

## P1-01 — Library (2026-10-15)
- **Home is now the library.** "Add PDF" opens the system file picker; Audora keeps a lasting read grant for the file (it is not copied) and lists the book with its title (from the file name), page count once opened, and when it was last opened or added. Most recently used first. Each row's menu has "Remove from library" (asks first; the PDF stays on the phone, the grant is given back).
- **Books are recognized by content, not by location:** fingerprint = SHA-256 of the file size plus its first 1 MiB (`LibraryConfig`), so adding a 1,300-page book costs the same as a 10-page one. Picking the same PDF again says "already in your library"; the same PDF from another folder or app moves the existing book there ("Found it again"), so its reading position (P1-06) survives. A file overwritten in place keeps its book. Files without a `%PDF-` header in the first 1024 bytes are refused.
- **Moved or deleted files:** every time the library is shown, each book's file is checked (grant still held, file still opens). A missing file's row says "File moved or deleted. Tap to find it."; a lost grant says "Audora can no longer open this file. Tap to pick it again." Tapping opens the picker; the same PDF relinks the book, a different PDF is refused with a clear message. Apps that only lend a file for a moment (no lasting grant) get "Save the PDF to your phone first".
- **Opening a book** (until the reader in P1-05) shows the P1-02 extraction check for that book: password prompt, page count, first sentence. A successful open records the page count and moves the book to the top. The old "Open a PDF to test" button is gone.
- **Where the code lives:** rules in `:core` (`core.library`: `Library`, `BookPlacement`, `DocumentScanner`, `BookFingerprinter`, `BookTitles`; pure Kotlin, JVM-tested); Room database and the Storage Access Framework adapter in `:playback` (`playback.storage`, `playback.documents`), because P1-06 stores resume anchors in the same database next to their books; `:app` has only UI state holders and screens. Room types never leave `:playback` (`AudoraStorage` hands out a `BookStore`). New convention plugin `audora.room` (KSP + Room from the catalog, schema export). `:core` now exposes kotlinx-coroutines (already in the catalog) for `Flow` and `suspend` contracts. No new libraries.
- **Navigation:** Library, Book and Settings are a saveable route string (`AppDestination`), no navigation library; if P1-05 makes the graph deeper, that is when to ask for Navigation Compose. Settings now also shows the app version.
- **Database:** `audora.db` version 1, table `books` with unique URI and unique fingerprint. Schemas are exported to `playback/schemas/` and committed; a new CI step fails when the build produces a schema file that is not committed, so every migration has a schema to start from. No destructive migration fallback.
- Tests: JVM tests for the library rules (add, duplicate, found again, changed in place, not a PDF, one-time grants, storage failure, missing vs lost grant, relocate same/different/stale entry, remove, ordering, unknown size), the fingerprint (head-only read, size and header window) and titles (table-driven, Devanagari and Bengali names). Device tests (emulator job, now also `:playback:connectedDebugAndroidTest`): the Room table's order, unique keys as typed errors, round trip, update and delete.
- Logs carry book ids (`book=3f2a9c01`) and provider authorities only, never titles or document URIs (which spell out file names).

**Known limits:** the file check runs one provider call per book in sequence (fine for hundreds of books). A book added while the app is killed mid-add can leave one unused grant (Android allows 512); adding the same file again reuses it.

## P1-07 — Diagnostics (2026-10-15)
- **Settings → Share logs:** a gear on the home screen opens Settings; "Share logs" zips a `summary.txt` (app version, phone, Android version, unfinished read, last 10 process exits) and the rolling log files into `cacheDir/shared-logs/` and opens the share sheet through a FileProvider limited to that folder. One zip, because every chat and mail app takes a single attachment and text logs compress about tenfold. The log queue is flushed first so the newest lines are included. No PDF text or book titles go into the log or the summary.
- **Process deaths are logged:** at every process start (background thread) Audora reads Android's `ApplicationExitInfo` history and writes each exit not yet logged: kind (SIGNALED, LOW_MEMORY, CRASH, CRASH_NATIVE, ANR, USER_REQUESTED, FREEZER…), signal/exit status, importance (e.g. `FOREGROUND_SERVICE(125)`, the OEM-kill signature), memory and Android's description. Abnormal kinds are warnings. A cursor in `filesDir/diagnostics/state.properties` makes each exit appear once.
- **Unfinished-session detection:** `ReadingSessionTracker` (`:core`) keeps an "audio is playing" marker on disk (atomic write + fsync). A marker found by a new process means the old one died mid-read: the log gets "Reading stopped unexpectedly: book=… page=…; cause: <exit>" and the app shows "Reading stopped unexpectedly — resume?". Paused sessions are not markers, so Android reclaiming a paused app never triggers the prompt.
- **Hooks for later tickets:** P1-04's playback service must call `onPlaybackActive(bookId, page)` on play and page change and `onPlaybackInactive()` on pause, stop, end of book and sleep timer. P1-06 makes "Resume" start playback at the `ResumeAnchor` (`TODO(P1-06)` in `DiagnosticsController`); until then Resume only closes the prompt.
- **Debug builds only:** Settings has "Simulate a reading session", which sets the marker without audio so the prompt and the exit logging can be checked on a phone before P1-04.
- Settings is a second screen switched by state and closed with back; P1-01 replaces it with real navigation. No new dependencies.
- Tests: JVM tests for the state file (round trip, corrupt file, stale temp file, unwritable folder), the tracker (dies while playing, paused, page change, repeated deaths, resolve), startup exit logging (once per exit, levels, cause selection), the zip writer and the summary; an app unit test for the Android reason/importance mapping.

**Real-device checks (Moto Edge 50 Fusion, dev build):** (1) Home → gear → Share logs → pick an app: the zip arrives and holds `summary.txt` plus `audora.log`. (2) Settings → "Simulate a reading session", then App info → Force stop, reopen Audora: the "Reading stopped unexpectedly" prompt names page 14; Share logs again: the log has "Previous process ended: USER_REQUESTED…" and "Reading stopped unexpectedly…".

## P1-02 — PDF text extraction (2026-10-15)
- `:pdf` reads a PDF one page at a time through PdfiumAndroidKt and turns each page into `ReadingUnit`s (sentence-sized, `charStart`/`charEnd` into the page text, language, line boxes). No layout heuristics yet (P2).
- JNI library `libaudora_pdfium_ext.so` (`pdf/src/main/cpp/`) over PdfiumAndroidKt's own `libpdfium.so`, loaded with `dlopen`/`dlsym` so no PDFium headers or second PDFium copy: per char the generated flag, Unicode-map errors, render mode, font name and size; per text object its `/ActualText` (outermost marked span, form XObjects included). 16 KB aligned, NDK pinned in `libs.versions.toml`.
- `/ActualText` rebuild (ADR-011 §2): PDFium's fake spaces inside Indic words are replaced by each span's `/ActualText`; if any text object cannot be aligned the page keeps PDFium's text (`ALIGNMENT_FAILED`, logged). On the UDHR test files Hindi and Bengali go from 13 % / 22 % word errors to ≤ 1 % CER.
- `PdfBook`: page-at-a-time reading, reopens the document every 100 pages (`ExtractionConfig.reopenEveryPages`), typed errors (`PdfOpenError`, `PdfPageError`) in an `Outcome` result in `:core`.
- Password prompt: the app's placeholder screen has an "Open a PDF to test" button (SAF picker) that opens the file, asks for a password if needed (never saved), and shows for the first 3 pages: page count, sentences, `/ActualText` spans, Unicode-map errors, time taken and the first sentence.
- `PIPELINE_VERSION = 1`.
- Tests: JVM tests on PDFium output captured from the three UDHR PDFs (rebuild, assembler, PDFDocEncoding, script detection, sentence units, `PdfBook` reopen/password/error paths). Device tests (`./gradlew :pdf:connectedDebugAndroidTest`, new CI job "Device tests (emulator)" on an x86_64 API 34 emulator): English/Hindi/Bengali UDHR at ≤ 1 % CER per page, encrypted PDF password flow, damaged/missing files, and a generated 500-page PDF read with a reopen every 100 pages (native heap growth ≤ 24 MB, Java ≤ 16 MB, and reopening never uses more native memory than staying open). Measured numbers are in the job's log under `AudoraMemoryTest`.
- New test-only dependencies: `androidx.test:runner`, `androidx.test.ext:junit`. `kotlinx-coroutines-core` added to `:pdf` because PdfiumAndroidKt's POM leaves it out.

**Known risks:** the JNI layer uses PdfiumAndroidKt's "unlocked" API (`PdfDocumentU`/`PdfPageU` native pointers) and its global lock; a library upgrade must re-run the device tests. PdfiumAndroidKt 2.0.3 brings kotlin-stdlib 2.4.x into a Kotlin 2.3 build (supported by Kotlin's forward metadata compatibility). Footers and headers are still read aloud (P2).

**Real-device checks (Moto Edge 50 Fusion):** install the dev build, tap "Open a PDF to test" and open (1) an English PDF, (2) a Hindi and a Bengali Unicode PDF: the first sentence shown has whole words, not split into pieces, (3) a password-protected PDF: the prompt appears, a wrong password says so, the right one opens it; (4) a 400+ page book opens without lag.

## P0-02 — Signed releases (2026-10-15)
- `.github/workflows/release.yml`: run from `prod` (Actions → Release → Run workflow) or push a `v*` tag on `prod`. Builds and signs `:app:assembleRelease`, checks 16 KB alignment and the signer certificate, publishes `audora-vX.Y.Z-arm64.apk` + `SHA256SUMS.txt` to GitHub Releases. Refuses commits not on `prod` and tags that differ from the version.

Publishing runs in a separate job without the secrets, using the `gh` CLI like the dev-build job instead of `softprops/action-gh-release` (one fewer third-party action with write access).
