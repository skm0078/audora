# Audora — Progress

One entry per merged ticket, newest first. Each entry: what changed, what was verified, what still needs a real-device check.

## P1-05 — Reader screen (2026-10-15)
- **Opening a book now opens the reader** (replaces the P1-02 extraction check, whose screen and strings are gone; the password prompt moved to `ui/reader`). It shows one page at a time as a list of its sentences, "Page N of M" with previous/next arrows, and a "Go to page" dialog (tap the page number). A password-protected book asks for its password first; the password stays in memory only and goes to the player with each start request.
- **Start from page N / tap a sentence:** tapping a sentence reads from it; Play reads from the top of the page on screen, or resumes where reading paused if that is the page shown. The screen follows the sentence being read (highlighted, scrolled into view, pages turn with it); browsing to another page stops following and offers "Back to page N, where reading is".
- **Controls:** play/pause, previous/next sentence, speed 0.5×–3× (`ReaderConfig`, applied by the player's Sonic time-stretch, C6, so a change is heard at once with no re-synthesis; the last speed is kept in a Preferences DataStore and re-applied when the player connects), sleep timer: 15/30/60 min or end of page. The notification permission is asked on the first play (Android 13+); reading does not depend on the answer.
- **Seam with the playback service (P1-04):** the reader uses only the standard Media3 `MediaController` API plus `playback.contract`: `PlaybackAddress` (media id `audora://book/<id>/page/<p>/char/<charStart>`, also the id of every playlist item; the service expands a start request into the playlist from the unit containing `charStart`), `PlaybackContract` extra keys (password, char end, page count) and `ReaderSessionCommands` (the one custom command, set sleep timer; its state comes back in the session extras). The session service is found by package, not by class.
- **Sleep timer runs in the service** (`playback.sleep`): `SleepTimer` (pure rules) + `PlayerSleepTimer` (Media3 binding the service creates). It never stops mid-sentence: when time is up it arms ExoPlayer's pause-at-end-of-item. Minutes are wall-clock and count while paused; a deadline that passed while the phone slept is honored on the next play. End of page re-checks the page boundary whenever the playlist grows. End of chapter needs headings or the PDF outline and waits for P2-02.
- New catalog-pinned libraries used: `media3-session` (`:app`, and `api` in `:playback` for the contract), `datastore-preferences` (`:app`). `POST_NOTIFICATIONS` declared.
- Tests: JVM tests for the reader model (open, not in library, password flow, failures, page picker clamping, start from page N, tap a sentence, resume vs restart, following and browsing, another book in the player, saved speed applied/rounded, controls), the sleep timer (finish the sentence, paused deadline, slept-through deadline, end of page re-arming, off/replace, publishing), the address codec and the control labels.

**Known limits:** until P1-04 is merged the player is not there and the reader shows "The player is not available". The reader opens at page 1 unless the book is already playing (resume anchor is P1-06). The reader and the service each open the PDF; both use the same :pdf pipeline, so their sentence offsets match.

**Real-device checks (Moto Edge 50 Fusion, dev build, after P1-04):** (1) Open a 50+ page English PDF, tap the page number, go to page 20, press Play: reading starts at the top of page 20. (2) Tap the third sentence on a page: reading jumps there and it is highlighted. (3) Change speed to 2× while reading: the voice speeds up within a second, with no gap or restart; back to 1×. Close and reopen Audora: the speed is still what you picked. (4) Previous/next sentence buttons. (5) Browse to another page while reading: the screen stays there and offers "Back to page N"; tap it. (6) Sleep timer "End of page": reading stops after the last sentence of the page, not mid-sentence. (7) Sleep timer 15 min with the screen off: reading stops at a sentence end around 15 min. (8) First play on a fresh install asks for notifications; saying no still plays. (9) A password-protected PDF: password prompt, then reading works.

## P1-01 — Library (2026-10-15)
- **Home is now the library.** "Add PDF" opens the system file picker; Audora keeps a lasting read grant for the file (it is not copied) and lists the book with its title (from the file name), page count once opened, and when it was last opened or added. Most recently used first. Each row's menu has "Remove from library" (asks first; the PDF stays on the phone, the grant is given back).
- **Books are recognized by content, not by location:** fingerprint = SHA-256 of the file size plus its first 1 MiB (`LibraryConfig`), so adding a 1,300-page book costs the same as a 10-page one. Picking the same PDF again says "already in your library"; the same PDF from another folder or app moves the existing book there ("Found it again"), so its reading position (P1-06) survives. A file overwritten in place keeps its book. Files without a `%PDF-` header in the first 1024 bytes are refused.
- **Moved or deleted files:** every time the library is shown, each book's file is checked (grant still held, file still opens). A missing file's row says "File moved or deleted. Tap to find it."; a lost grant says "Audora can no longer open this file. Tap to pick it again." Tapping opens the picker; the same PDF relinks the book, a different PDF is refused with a clear message. Apps that only lend a file for a moment (no lasting grant) get "Save the PDF to your phone first".
- **Opening a book** (until the reader in P1-05) shows the P1-02 extraction check for that book: password prompt, page count, first sentence. A successful open records the page count and moves the book to the top. The old "Open a PDF to test" button is gone.
- **Where the code lives:** rules in `:core` (`core.library`: `Library`, `BookPlacement`, `DocumentScanner`, `BookFingerprinter`, `BookTitles`; pure Kotlin, JVM-tested); Room database and the Storage Access Framework adapter in `:playback` (`playback.storage`, `playback.documents`), because P1-06 stores resume anchors in the same database next to their books; `:app` has only UI state holders and screens. Room types never leave `:playback` (`AudoraStorage` hands out a `BookStore`). New convention plugin `audora.room` (KSP + Room from the catalog, schema export). `:core` now exposes kotlinx-coroutines (already in the catalog) for `Flow` and `suspend` contracts. No new libraries.
- **Navigation:** Library, Book and Settings are a saveable route string (`AppDestination`), no navigation library; if P1-05 makes the graph deeper, that is when to ask for Navigation Compose. Settings now also shows the app version.
- **Database:** `audora.db` version 1, table `books` with unique URI and unique fingerprint. Schemas are exported to `playback/schemas/` and committed; a new CI step fails when the build produces a schema file that is not committed, so every migration has a schema to start from. No destructive migration fallback.
- Tests: JVM tests for the library rules (add, duplicate, found again, changed in place, not a PDF, one-time grants, storage failure, missing vs lost grant, relocate same/different/stale entry, remove, ordering, unknown size), the fingerprint (head-only read, size and header window) and titles (table-driven, Devanagari and Bengali names). Device tests (emulator job, now also `:playback:connectedDebugAndroidTest`): the Room table's order, unique keys as typed errors, round trip, update and delete.
- Logs carry book ids (`book=3f2a9c01`) and provider authorities only, never titles or document URIs (which spell out file names).

**Known limits:** the file check runs one provider call per book in sequence (fine for hundreds of books). A book added while the app is killed mid-add can leave one unused grant (Android allows 512); adding the same file again reuses it.

**Real-device checks (Moto Edge 50 Fusion, dev build):** (1) Add PDF → pick an English PDF: it appears; tap it: the check shows its pages; back: the row shows the page count. (2) Close Audora (swipe away), reopen: the book is still listed. (3) In the Files app move that PDF to another folder, return to Audora: the row says "File moved or deleted"; tap it, pick the moved file: "Found … again", and it opens. (4) Delete a PDF that is in the library: the row turns red. (5) Add the same PDF twice: "already in your library". (6) Remove a book: it disappears; the file is still in Files. (7) Add a password-protected PDF and open it: the password prompt appears.

## P1-07 — Diagnostics (2026-10-15)
- **Settings → Share logs:** a gear on the home screen opens Settings; "Share logs" zips a `summary.txt` (app version, phone, Android version, unfinished read, last 10 process exits) and the rolling log files into `cacheDir/shared-logs/` and opens the share sheet through a FileProvider limited to that folder. One zip, because every chat and mail app takes a single attachment and text logs compress about tenfold. The log queue is flushed first so the newest lines are included. No PDF text or book titles go into the log or the summary.
- **Process deaths are logged:** at every process start (background thread) Audora reads Android's `ApplicationExitInfo` history and writes each exit not yet logged: kind (SIGNALED, LOW_MEMORY, CRASH, CRASH_NATIVE, ANR, USER_REQUESTED, FREEZER…), signal/exit status, importance (e.g. `FOREGROUND_SERVICE(125)`, the OEM-kill signature), memory and Android's description. Abnormal kinds are warnings. A cursor in `filesDir/diagnostics/state.properties` makes each exit appear once.
- **Unfinished-session detection:** `ReadingSessionTracker` (`:core`) keeps an "audio is playing" marker on disk (atomic write + fsync). A marker found by a new process means the old one died mid-read: the log gets "Reading stopped unexpectedly: book=… page=…; cause: <exit>" and the app shows "Reading stopped unexpectedly — resume?". Paused sessions are not markers, so Android reclaiming a paused app never triggers the prompt.
- **Hooks for later tickets:** P1-04's playback service must call `onPlaybackActive(bookId, page)` on play and page change and `onPlaybackInactive()` on pause, stop, end of book and sleep timer. P1-06 makes "Resume" start playback at the `ResumeAnchor` (`TODO(P1-06)` in `DiagnosticsController`); until then Resume only closes the prompt.
- **Debug builds only:** Settings has "Simulate a reading session", which sets the marker without audio so the prompt and the exit logging can be checked on a phone before P1-04.
- Settings is a second screen switched by state and closed with back; P1-01 replaces it with real navigation. No new dependencies.
- Tests: JVM tests for the state file (round trip, corrupt file, stale temp file, unwritable folder), the tracker (dies while playing, paused, page change, repeated deaths, resolve), startup exit logging (once per exit, levels, cause selection), the zip writer and the summary; an app unit test for the Android reason/importance mapping.

**Real-device checks (Moto Edge 50 Fusion, dev build):** (1) Home → gear → Share logs → pick an app: the zip arrives and holds `summary.txt` plus `audora.log`. (2) Settings → "Simulate a reading session", then App info → Force stop, reopen Audora: the "Reading stopped unexpectedly" prompt names page 14; Share logs again: the log has "Previous process ended: USER_REQUESTED…" and "Reading stopped unexpectedly…".

## P1-02 — PDF text extraction (2026-10-15)
- `:pdf` reads a PDF one page at a time through PdfiumAndroidKt and turns each page into `ReadingUnit`s (sentence-sized, `charStart`/`charEnd` into the page text, language, line boxes). No layout heuristics yet (P2).
- JNI library `libaudora_pdfium_ext.so` (`pdf/src/main/cpp/`) over PdfiumAndroidKt's own `libpdfium.so`, loaded with `dlopen`/`dlsym` so no PDFium headers or second PDFium copy: per char the generated flag, Unicode-map errors, render mode, font name and size; per text object its `/ActualText` (outermost marked span, form XObjects included). 16 KB aligned, NDK pinned in `libs.versions.toml`.
- `/ActualText` rebuild (ADR-011 §2): PDFium's fake spaces inside Indic words are replaced by each span's `/ActualText`; if any text object cannot be aligned the page keeps PDFium's text (`ALIGNMENT_FAILED`, logged). On the UDHR test files Hindi and Bengali go from 13 % / 22 % word errors to ≤ 1 % CER.
- `PdfBook`: page-at-a-time reading, reopens the document every 100 pages (`ExtractionConfig.reopenEveryPages`), typed errors (`PdfOpenError`, `PdfPageError`) in an `Outcome` result in `:core`.
- Password prompt: the app's placeholder screen has an "Open a PDF to test" button (SAF picker) that opens the file, asks for a password if needed (never saved), and shows for the first 3 pages: page count, sentences, `/ActualText` spans, Unicode-map errors, time taken and the first sentence.
- `PIPELINE_VERSION = 1`.
- Tests: JVM tests on PDFium output captured from the three UDHR PDFs (rebuild, assembler, PDFDocEncoding, script detection, sentence units, `PdfBook` reopen/password/error paths). Device tests (`./gradlew :pdf:connectedDebugAndroidTest`, new CI job "Device tests (emulator)" on an x86_64 API 34 emulator): English/Hindi/Bengali UDHR at ≤ 1 % CER per page, encrypted PDF password flow, damaged/missing files, and a generated 500-page PDF read with a reopen every 100 pages (native heap growth ≤ 24 MB, Java ≤ 16 MB, and reopening never uses more native memory than staying open). Measured numbers are in the job's log under `AudoraMemoryTest`.
- New test-only dependencies: `androidx.test:runner`, `androidx.test.ext:junit`. `kotlinx-coroutines-core` added to `:pdf` because PdfiumAndroidKt's POM leaves it out.

**Known risks:** the JNI layer uses PdfiumAndroidKt's "unlocked" API (`PdfDocumentU`/`PdfPageU` native pointers) and its global lock; a library upgrade must re-run the device tests. PdfiumAndroidKt 2.0.3 brings kotlin-stdlib 2.4.x into a Kotlin 2.3 build (supported by Kotlin's forward metadata compatibility). Footers and headers are still read aloud (P2).

**Real-device checks (Moto Edge 50 Fusion):** install the dev build, tap "Open a PDF to test" and open (1) an English PDF, (2) a Hindi and a Bengali Unicode PDF: the first sentence shown has whole words, not split into pieces, (3) a password-protected PDF: the prompt appears, a wrong password says so, the right one opens it; (4) a 400+ page book opens without lag.

## P0-02 — Signed releases (2026-10-15)
- `.github/workflows/release.yml`: run from `prod` (Actions → Release → Run workflow) or push a `v*` tag on `prod`. Builds and signs `:app:assembleRelease`, checks 16 KB alignment and the signer certificate, publishes `audora-vX.Y.Z-arm64.apk` + `SHA256SUMS.txt` to GitHub Releases. Refuses commits not on `prod` and tags that differ from the version.
- Version: `audora.versionName` in `gradle.properties` is the single source; `versionCode` is derived (`MAJOR*1000000 + MINOR*1000 + PATCH`).
- Signing secrets (`KEYSTORE_B64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`, spec §7) live in a GitHub environment `release` limited to `prod` and `v*`, so a workflow edited on a feature branch cannot read them. Publishing runs in a separate job without the secrets, using the `gh` CLI like the dev-build job instead of `softprops/action-gh-release` (one fewer third-party action with write access).
- Key runbook and Windows key script (no Android Studio): `docs/RELEASING.md`, `scripts/release/new-release-key.ps1` (PKCS12, RSA 4096, ~27 years, random 32-char password, never overwrites an existing key).
- Android CI now also builds the unsigned release APK on every push, and ignores tags.
- Verified: key script end to end under PowerShell 7 with the JDK `keytool` (key created, secrets copied, base64 round-trip, re-run keeps the key); actionlint + shellcheck on both workflows; ktlint. The release build itself is verified only in CI.

**Pending (user):** one-time key setup and backups and ruleset change (docs/RELEASING.md steps 1–4), dev → prod PR, run the Release workflow; key created and backed up 2026-10-15 and its certificate pinned in release.yml.

**Real-device checks:** Obtainium installs `audora-v0.0.1-arm64.apk` on the Moto Edge 50 Fusion next to the dev build; the app opens.

## P0-01 — Repo scaffold + CI (2026-10-14)
- Five modules (`:app`, `:playback`, `:speech`, `:pdf`, `:core`) wired `app → playback → (speech, pdf) → core`. `:core` is a pure JVM module; the others are Android modules.
- Convention plugins in `build-logic/`; every version in `gradle/libs.versions.toml` (AGP 9.4.0, Gradle 9.8.1, Kotlin 2.3.21, KSP 2.3.12, Hilt 2.60.1, Compose BOM 2026.09.00; Media3 1.11.1, Room, DataStore, WorkManager, PdfiumAndroidKt pinned for later tickets).
- compileSdk 37 (targetSdk stays 36): current AndroidX requires it, see ADR-010.
- Hilt + Compose app shell: `AudoraApplication`, `MainActivity` (edge-to-edge, predictive back), placeholder screen, dynamic color.
- Logging: `AudoraLog` facade in `:core`, logcat sink, rolling file `filesDir/logs/audora.log` (2 MB × 3), uncaught exceptions written to the file before the crash.
- Quality gates: ktlint 1.8.0 and detekt 1.23.8 run as CLIs from the root build (`ktlintCheck`, `ktlintFormat`, `detekt`).
- CI (`.github/workflows/android.yml`): ktlint, detekt, unit tests, debug APK, 16 KB alignment + arm64-only check, APK artifact.
- Branches: `dev` (default, stable code, ticket PRs land here) and `prod` (releases; tags from P0-02 are cut here).
- Docs moved into the repo: spec, ticket plan, decisions, v0.1 archive, research notes.

**Real-device checks:** install the CI debug APK on the OnePlus 12; it opens and shows the placeholder screen; the launcher icon renders (including themed icons); `adb logcat -s` shows an `Audora.AppLogging` start line.

**Known gaps:** 16 KB check passes trivially until native libraries arrive (S1/P1-02); its own unit tests prove it rejects bad APKs. Signed release builds are P0-02.
