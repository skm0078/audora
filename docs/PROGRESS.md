One entry per merged ticket, newest first. Each entry: what changed, what was verified, what still needs a real-device check.

## Reading intelligence, step 8 — scanned pages: headings, lists, note markers, Bengali sentence ends; close table columns (RI-10, RI-5a, RI-3, RI-4a; 2026-10-17, ADR-035)
- **Headings from type size:** Tesseract's estimate of each line's type size is kept with the OCR text, and a clearly read line well above the page's body size (1.3×, `LayoutConfig.ocrHeadingSizeRatio`) becomes a heading, split from the paragraph under it. Large lines read badly, starting with a pointer ("> click here"), holding a table bar or ending a sentence stay body text (screenshots, stamps, noise).
- **Bullets OCR misread restored:** the Hindi and Bengali models have no bullet, so "•" came out as "o", "०", "০", "*", "+", "°" or "©" and was read aloud ("zero") before every item. A line starting with one of those, then a word, now starts a list item and the bullet is silent (`OcrBullets`).
- **Note markers on scanned pages left out:** OCR glues a superscript marker to its word as a sign ("Vaswani*", "Eich*,", "Smith#,", "Haghighat®,", "double.!"), which was read aloud. Those signs, and a small raised star or dagger set right after a word, are now left out (`OcrNoteMarkers`, the text layer's size and rise thresholds); digits glued to a word ("Fig.1") and raised numbers are kept. On 364 scanned and rendered test pages every one of the 51 changed lines was a marker or a required-field star.
- **Bengali sentence ends on scanned pages:** Tesseract reads a line-end danda as "৷" (a look-alike sign) or, on poor scans, a lone "|" after a misread word, so the sentence ran on into the next; those now end the sentence (`OcrDandas`; a "|" between Latin words or digits stays a separator, and one whose next line closes a bracket it never opened is that "("). It also reads the vowel sign aa (the same bar) as "!", "|" or "৷" glued to a word, which made a false stop and the wrong word ("কর! এবং" for "করা এবং", "ধার৷ ১৯" for "ধারা ১৯"); a bar running on to the next word on the line is now the sign, or dropped when it repeats the sign (`OcrAaBars`). On the 20 Bengali UDHR scan pages: sentences running on 4 → 2, false stops 14 → 0, character errors 1.12% → 0.91%. Hindi already lost almost no sentence ends (0 of 104 at 300 dpi), so it is unchanged. The listening corpus gains a scanned Bengali page pair (`bn-udhr-scan200bad-p4-5`, 0.9820; 0.9814 without these repairs), so CI now guards Bengali scanned reading; its score counts words, so the removed false stops show only as 30 → 28 units.
- **Table columns set close together are split:** two columns closer than a cell gap, or under one header cell, read as one ("1 Assam"). Where a gap wider than a word space runs down the column, it is split (`ColumnChannels`); the Jal Shakti report's serial numbers and states are now two columns, and no other table changed.
- **Review fixes (tables, retries, markers, rotation):** a line set close above a table ("The rates are as follows:") is read before it, the line after it starts a new paragraph, and a second table keyed in the same paragraph is no longer dropped. Two tables side by side stay two: on scanned pages rules in line but more than 2 em apart (`TableConfig.ruleBreakEm`) are separate rules, and on text pages two runs of rows are joined only when they overlap or sit no farther apart than twice their own column gap (`sideBySideGapRatio`); a block of cells spanning rows still joins its table. Two tables side by side on the same row heights, which layout joins row by row, are split at the gutter and read as two tables when the gutter is more than twice their widest column gap and they show it (`TableSides`: the same header on both halves of a list, or a row of two or more cells on one side only, below the header and unless the right side is all figures); a single table with a wide gap before its figures stays one, and so does one with section rows ("A. | Revenue receipts"), blank figures ("–", "..", "N.A.") or a header over two lines. Two runs XY-cut cut apart across a wide gutter are joined only when the right one is figures under its own header (`TableConfig.minFigureRows` rows, no serial number opening them). When one side of a split is too sparse for a table it stays text, unless it shares lines with the other side: then the whole is read as one table, so no words are lost. On the test PDFs this separates a directory and an office table on the Chhattisgarh diary's contacts page and a rubric beside an assignment table on the Bengali textbook notice, with no words lost. A one-character cell beside a ruled line ("5", a serial number) is read; only bar-like marks ("|", "।", "৷", "!", "l", "I", "[", ":") are taken for the rule. Scanned pages with `/Rotate` 90 or 270 find their tables and bullets as upright pages do. An exponent after a two-letter name next to an operator ("E = mc²", "ax² + bx") is kept, and "+" alone is a charge, not a marker. Running headers in the margin strips get the line retry too, so a header the page's retry cleaned up is still recognised; letterless lines no longer use up the retry limit; each model loads once per page; a page read before another model was installed is read again.
- **Footnotes on scanned pages:** the text-layer rule now runs on OCR's line sizes and boxes (`OcrFootnotes`). Lines set smaller than the body at the foot of a column (within 12% of the page's height from its foot, `NoteConfig.ocrFootnoteBandShare`), with nothing below them and set apart from the line above, are footnotes when they are also placed like notes: a run with no marker must start flush with its column or under a rule (block quotes, verse and epigraphs set small are indented or centred), and a run of fewer than three lines needs a second sign: a note sign ("*", "†"), a rule above it (`OcrText.rules`) or lines closer together than the body's (`ocrNoteSpacingRatio`); a lone small line starting with a number ("15 अगस्त…") is body text. Letters must be read with at least 70 mean confidence, or the page's own mean less 20 when lower (Hindi and Bengali small print). Each OCR paragraph starts a note, and so does a line whose marker continues the numbering (2 after 1); any other number at a line start ("12 pages…", "11 SCC 345") is read. Captions, "Source:" lines and small bulleted lists stay as they were. Printers' slugs at a scanned page's foot ("….indd", "5/13/11 6:45 AM") are dropped as clutter (`OcrClutter`). On the 130 rendered and scanned pages it keeps every footnote it found on attention, forallx, tracemonkey and landrev and drops 20 false ones (slugs, a running footer, logo junk). Known miss: jmathbiol's corresponding-author block, whose run opens with an e-mail line that has no marker, rule or flush start. Book kinds, golden and listening are unchanged.
- **Tables and sentences carried over a page break:** each page is joined to what the page before it hands on (`PageCarry`, in `PdfBook.readPage`). When that page has not been read, its hand-on is worked out by reading it quietly (no OCR beyond the cache, no change to the book's text-layer verdict) and, when it opens with a table too, from its own page before, up to `PageCarryConfig.maxCarryPages` back; so the reader, playback and export read a page the same whichever page came before. A hand-on is kept for reuse only when built from a complete chain under the text-layer verdict still in force; one cut short (past the limit, a page that failed to read, a scanned page read only from the OCR cache) is used once and worked out again next time, and the page before is looked at only when this page opens with a table or with body text. A quiet look reads the OCR cache without the page lock or refreshing its date and never sets the book's languages. The continued summary has no length, so the reader keys its sentence list by unit index and playback counts an empty unit as one character (`ReadingUnit.spokenEnd`, as on the player branch), so resuming at row 0 plays "Table continues" first. A table that ends one page and opens the next with the same columns continues, unless a caption that does not say "contd."/"जारी"/"ক্রমশ" stands before it: when the header row is repeated (more than half of its cells and at least two), every unit of it is marked `TableRowInfo.continued` with `rowsBefore`; when the next page opens with data (a serial number continuing the last row, or cells written like the column's data with no header years such as "2018-19"), a continued summary unit of no length is set at the first row's start and that row becomes data row 0 under the carried header. Every continued table therefore opens with a continued `TABLE_SUMMARY`. A table whose own first row is data hands on no header. `PageReading.continuesPreviousPage` (also `BookText.reading`) says the page opens inside the sentence the page before broke off (at least three words, ending on a letter, comma or dash, the next page in the same kind and lower case; in Hindi and Bengali the last line must reach the column's right edge and the next page's first line must not be indented). On the salary list (13 pages) all seven continuation pages carry their table; on the 57 kind PDFs page breaks marked as continuing drop from 56 to 44, the dropped ones new paragraphs, form fields and a chapter heading.
- **"Note:" asides on scanned pages:** a body paragraph opening with a note label ("Note:", "नोट -", "टिप्पणी:", "দ্রষ্টব্য:") is an aside on a scanned page too, by the text layer's rule (`NoteFinder.opensWithNoteLabel`); two Hindi notes on the test scans.
- **Page labels:** `PdfBook.pageLabels()` gives each page's printed label from the PDF's page labels ("iv", "A-3"; null where it has none), read through `FPDF_GetPageLabel` with no page loaded, so copies and "Go to page" can use the numbers printed on the pages. The symbol is optional: a libpdfium.so without it reads as no labels. Reading units are unchanged.
- **Book kinds** on the 57 test PDFs: 51 right (89.5%), from 49; both scanned textbooks are now textbooks and no right answer changed. Still one PDF short of the ticket's 90%; the six misses are not about structure (listed in ADR-035).
- `PIPELINE_VERSION` 11 (OCR'd pages change: headings, list items, silent bullets and markers, Bengali sentence ends and vowel signs; text-layer tables with close columns). OCR cache format v4 (line sizes), older entries still decode. Golden 0.9268, listening 0.9783, the English and Hindi UDHR character error rates unchanged (Bengali improved, above). No new dependency.

## Quiz me and character guide (plan items 70 offline half, 80 list; 2026-10-18, ADR-048 for 70)
- **Quiz me (70):** *Quiz me* in the library's ⋮ menu turns every highlight into a fill-in-the-blank question: the highlight's rarest word is left out, the question is read aloud in the listener's voice ("blank" in its language), and it is answered by tapping one of four words from the listener's other highlights in the same script, or by *Show answer* and *I knew it* when there are too few. Right answers come back after a day, 3 days, a week, 3 weeks and 60 days; a wrong one after 10 minutes. Up to 10 due cards per quiz, *Practise anyway* when none is due; a playing book pauses for each question. Progress is `files/quiz-progress.txt` (backed up). No download, no new library (`QuizCards`, `QuizSchedule`, `QuizRound`, `QuizProgressStore`, `QuizSpeaker`, `QuizModel`; 9 JVM tests).
- **Character guide (80):** *Character guide* in a book's menu keeps the listener's own who's-who list: name, who they are, and the page where they meet them (pre-filled with the book's resume page). Only characters met at or before the resume point are shown, by name; later ones are only counted ("2 more later in the book"), so the list never gives away who comes next. Tap to edit or delete. One small file per book under `files/character-guide/` (named by a hash of the book id, backed up); up to 500 characters per book. The automatic version needs the AI model (call 3) (`CharacterGuide`, `CharacterGuideStore`, `CharacterGuideModel`; 3 JVM tests).

## Wave 3 — highlights, search, voice notes, EPUB and text books, shared text, point and read, watched folders, dictionary, backup and restore (plan items 30, 16, 32, 42, 43, 62, 26, 33, 28; 2026-10-17, ADR-041 to ADR-047)
- **Highlights and quote export (30):** *Highlight* in the sentence menu marks the sentence (a soft band in the text view); *Export highlights and notes* in a book's menu writes `<title> - notes.md` and `.txt` (quotes, bookmark notes, page numbers) to Documents/Audora (`QuoteExport`). Room v4 adds `highlights` and `voice_notes` by auto-migration (schema `4.json`).
- **Search in the book (16):** *Search in book* in the reader's menu: every word must match, the last as a prefix, results while typing; a result opens its sentence. A per-book SQLite FTS4 index in `noBackupFilesDir/search/` is built while the search screen is open, 10 pages at a time, resumes next time, rebuilds on a new `PIPELINE_VERSION` or page count, and retries scanned pages whose OCR was not ready (`BookSearch`, `SqliteSearchIndex`, `SearchTerms`).
- **Voice notes (32):** *Record a voice note* in the sentence menu (asks for the microphone once) records AAC to `filesDir/voice-notes/`, up to 10 minutes, pausing playback; notes list under the bookmarks and play or open where they were recorded (`VoiceNoteAudio`, `VoiceNotesModel`).
- **EPUB and text books (43):** the picker, "Open with" and "Share" take `.epub` and `.txt` beside PDFs. The format is sniffed from the first bytes; `TextBooks` parses EPUB 2/3 (navigation or NCX titles, notes moved to the chapter end, tables read cell by cell, DRM refused) and text files (UTF-8 or Windows-1252, chapter lines in English, Hindi and Bengali) into pages of about 2,500 characters, so playback, resume, bookmarks, search, studio and exports work unchanged. The reader shows them in the text view.
- **Shared text (42):** text shared from a browser, chat or notes app is saved as a `.txt` book and opened; a share that is only a link says to share the selected text.
- **Point and read (62):** *Point and read (take a photo)* in the library's new ⋮ menu opens the camera app (no camera permission); the photo, turned upright and scaled to 3,000 px, is kept as JPEG in a one-page PDF with no text layer (`ImagePdf`, `PhotoBooks`), added and opened, and read by the existing scanned-page OCR path.
- **Watched folders (26):** *Watched folders* in the library's ⋮ menu lists chosen folders (*Add a folder*, *Remove*, *Pick again*). When the library opens (at most every 3 minutes, always right after a folder is added), new PDF and EPUB files there and in sub-folders (4 levels, 5,000 entries, 50 files tried per scan) join the library, read through the folder's grant; hidden files (MediaStore's `.trashed-` and `.pending-` copies) are skipped; a removed book is not added back, even when the folder is watched again; a file that fails (offline, still downloading) is retried after 1 hour, doubling to a week; a toast says how many joined. A folder whose grant is gone (revoked, or restored from a backup on a new phone) shows as unreachable with *Pick again*. Audora gives back only folder grants it took itself, once nothing needs them. Android's picker cannot grant the Download folder itself, so a folder inside it is watched. No background job (`WatchedFolders`, `FolderWalker`, `FolderScan`, `WatchedFolderStore`).
- **Dictionary on tap (33):** *Look up a word* in the sentence menu: the sentence's words as buttons, or type one; entries show parts of speech, definitions and synonyms. The English dictionary (Open English Wordnet 2025, CC BY 4.0) is an opt-in download, 5.4 MB, 16 MB on the phone, built reproducibly by `scripts/build_dictionary.py` and published by the voice-mirror workflow; looked up by binary search in the file with WordNet's base-form rules (`Dictionary`, `SortedLines`, `EnglishBaseForms`, `Dictionaries`). Hindi and Bengali: Hindi WordNet and IndoWordNet forbid redistribution (ADR-045), so each has its own opt-in download built from Wiktionary via kaikki.org (CC BY-SA 4.0): English meanings, parts of speech, synonyms and inflected forms; Hindi 1.8 MB (16 MB on the phone), Bengali 0.6 MB (3.3 MB). A tapped word goes to its script's dictionary; the snapshot is pinned by SHA-256 and kept once published, since kaikki.org replaces its files weekly (ADR-047).

## Pauses in unpunctuated scans — the opt-in punctuation model (RI-11; 2026-10-17, ADR-035)
- **What it does:** Settings → "Pauses in unpunctuated scans (English)" downloads a 7.5 MB model (Edge-Punct-Casing's English CNN-BiLSTM, int8, Apache-2.0, run by sherpa-onnx's online punctuation API); downloading is the opt-in and delete removes it. While it is installed, a sentence from an OCR page that is English, 40 words or longer and has no `. ? ! । ॥` inside gets the model's commas and question marks, so the voice pauses there (RI-6's clause pauses). Everything else, including every text-layer page and any sentence that already has a full stop, is never sent to it (`RunOnPunctuation`, `PunctuationConfig`).
- **Why so narrow:** measured on our English texts with punctuation stripped (the eval notes are kept with the project research, outside the repo), sentence ends scored F1 0.33 for this model and 0.27 for the 75 MB CT-Transformer, against the ticket's 0.85; about two of every three full stops land mid-sentence. So its full stops (and `! ; :`) are read as commas: a wrong one costs a short pause, not a broken sentence. The user's card offered "long runs only" (built), "all scanned text" and "rules only".
- **Safety:** only marks are taken from the model. Its words are matched one for one against the original; any changed, split or dropped word keeps the sentence as written, and the original spelling and case are kept (an acronym it lower-cases still reads as before). A model that fails to load or answer is logged once and the text reads as written. Logs carry the page and sentence, never the text.
- **Download:** pinned like the voices (SHA-256, resumable, WorkManager, `PunctuationModels`, `PunctuationDownloadJob`, `PunctuationFiles`, `noBackupFilesDir/punctuation/<sha12>`); only the zip's two model files are unpacked, capped. The zip is built by `scripts/build_voice_mirror.py` from `speech/models.json`'s new `models` list (tar.bz2 sources supported) and published to the `voices` release by the mirror workflow on dev, so the download works once this is merged. Credit added to the licences screen. The playback service and "Save as audiobook" both use it.
- Tests: `RunOnPunctuationTest`, `PunctuationDownloadTest` (pins match models.json, safe unpack, resume, give-up), `ReadingSetupTest`, the mirror script's tarball and `models` tests. Golden and listening scores unchanged (no `:pdf` change; the listening corpus is born-digital, so the model never runs there). No new dependency (sherpa-onnx already ships the API).
- **Gaps:** English only (no Hindi or Bengali punctuation model exists offline in sherpa-onnx); a danda or full stop from a scanned line end is the PDF pipeline's to restore, not this model's.
**Real-device checks (final phone session):** download the model from Settings and delete it; a scanned English page with no full stops (e.g. a photocopied notice) sounds less breathless with the model and unchanged without; a punctuated scan and a normal PDF sound the same either way; render speed on the Moto stays ahead of playback on a dense scanned page.

## Reading intelligence, step 7 — tables on scanned pages (RI-4a part 2; 2026-10-17, ADR-035)

## Reading intelligence, step 4 — footnotes and note markers (RI-5a; 2026-10-17, ADR-035)

## P4-03 — Sentence highlight on the rendered page (2026-10-16)

## P1-06 — Exact resume and battery onboarding (2026-10-15)
- **Audora remembers the sentence:** while reading, the playback service saves the current sentence of each book as a `ResumeAnchor` (page, sentence start, head and tail fingerprints, pipeline version) in a new `resume_anchors` table (database version 2, Room auto-migration, one row per book, deleted with the book). ## P1-04 — Playback service (2026-10-15)
- **Reading aloud works end to end:** the reader's Play / tap-a-sentence sends `PLAY_FROM` to `AudoraPlaybackService` (Media3 `MediaSessionService`, foreground type `mediaPlayback`), which opens the book through the library's file grant, extracts pages on one background thread (PDFium, P1-02) about a page ahead of the playhead, and reads sentence by sentence. Notification, lock screen, headset and Bluetooth buttons come from Media3's session (play/pause, previous/next sentence). Speed is the player's own (Sonic, C6).
- **Never ENDED while text remains (C5):** each playlist item is one sentence (a WAV served by `TtsDataSource`, which blocks until the render queue has it), and the playlist always ends with a "more is coming" placeholder that blocks until the next page is appended; only after the last page is it removed, so ENDED means the book is finished.
- **Render queue** (`RenderAheadQueue`): one worker thread renders the playing sentence plus 3 ahead (`QueueConfig.prefetchUnits`) with P1-03's `SpeechEngine`; a sentence that leaves the window mid-render is cancelled. Played sentences stay in an 8 MiB in-memory cache so skip-back is instant. Deviation from Build Spec §6 (20 MB disk LRU), recorded as ADR-016: memory only, because a disk cache of a user's book audio is one more thing to clean up and gains little for a sentence-level skip-back; revisit if skip-back of more than ~3 min is wanted.
- **Seek and voice change rebuild the queue:** every start, seek or `SET_VOICE` opens a new render epoch (new queue, new media ids `audora://book/<id>/e/<epoch>/…`); loads from an older epoch fail fast and are never played. A voice change restarts the current sentence in the new voice. English uses the bundled Piper voice by default, Hindi/Bengali the phone's best offline system voice (P1-03).
- **Recovery** (`PlaybackRecovery`): a sentence the engine cannot render is skipped (reported in the session extras), but 3 in a row stop reading with an error instead of skipping a whole book; a dead engine stops at once. Media3's stuck-buffering error (10 min, S3 finding 3) restarts the render queue at the current sentence, a second time on the same sentence skips it; "stuck" while Android suppresses audio (a phone call) just retries. Other player errors retry once.
- **Sleep timer runs in the service:** minutes (counted on `elapsedRealtime`, so deep sleep counts; when it runs out the sentence playing is finished first) or end of page (the player's pause-at-end-of-item).
- **Contract for the UI** (`playback.contract.PlaybackContract`): custom commands `PLAY_FROM`, `SET_VOICE`, `SET_SLEEP_TIMER` (only accepted from Audora's own package), each sentence's book/page/char range in its metadata extras, book/sleep timer/error in the session extras. The reader's `NoPlaybackPort` stand-in is replaced by `MediaControllerPlaybackPort`.
- **P1-07 hooks:** `onPlaybackActive(book, page)` while playing or buffering to play (and on every page change), `onPlaybackInactive()` on pause, stop, error, end and sleep timer; on a background thread.
- **Starts as soon as a sentence is rendered** (`QueueConfig.playbackStartBufferMs = 0`): with Media3's default start buffer (1 s, 2 s after a rebuffer) a run of short sentences never fills it, because the next sentence only renders once the playhead moves, so the player waited in BUFFERING forever. The emulator test found this.
- Wake lock: Media3's `WAKE_MODE_LOCAL` (S3 finding 4), no wake lock of our own. No boot start and no playback resumption from the system (P1-06). `<queries>` for the TTS service intent declared (Build Spec §6; P1-03 needs it to list system voices on Android 11+).
- Tests: JVM tests for the render queue (order, window, cancel, failure, recent cache, close), playlist feeding (placeholder swap, insert before placeholder, finish, trim behind), recovery rules, sleep timer, media ids, page cursor and WAV encoding. Device test (emulator job): the session on a real ExoPlayer with a fake book and voice reads every sentence in order and ends only after the last, starts at a char offset, rebuilds on a voice change, and skips a sentence that fails to render. No new dependencies.

**Known limits:** a 15- or 60-minute screen-off run can only be checked on a phone (below). Logs carry book ids, pages and sentence keys (`p12u3`), never the text.

**Real-device checks (Moto Edge 50 Fusion, dev build; batch with the S1/S3 phone run):** (1) Open an English PDF, press Play: reading starts within a few seconds and the notification shows the title and "Page N of M". (2) Screen off, phone on the table, 15 min (P1-04 done-when), then 60 min (Phase 1 done-when): reading never stops; Share logs afterwards. (3) Lock screen and notification play/pause/next/previous; wired or Bluetooth headset button pauses and resumes; unplugging the headset pauses. (4) Take a phone call while reading: it pauses and resumes after. (5) Go to page 20 while reading: reading jumps there. (6) Sleep timer 15 min with the screen off: stops at the end of a sentence. (7) A Hindi PDF with the phone's Hindi voice installed reads in Hindi; without it, the reader shows the error instead of silence. ## P1-03 — Speech engines (2026-10-15)
- **`SpeechEngine` contract** (`:speech`): `render(text, voice)` returns 16-bit mono PCM or a typed `SpeechError` (`VoiceUnavailable` with reason UNKNOWN_VOICE / NOT_INSTALLED / NETWORK_ONLY / MODEL_FILES_MISSING, `EngineUnavailable`, `SynthesisFailed`), each with a readable message. Renders are main-safe, serialized per engine and cancellable (the caller gets `CancellationException`, the engine stays usable). `VoiceId`/`EngineId` and `SpeechConfig` live in `:core` so resume anchors can store a voice.
- **Bundled neural voice** (`SherpaSpeechEngine`): sherpa-onnx 1.13.8, 2 threads, one model loaded at a time, loaded on first render. Cancellation stops between sherpa-onnx's internal sentences. Release never frees a model under a running render. The voice is chosen in `speech/bundled-voices.json` (provisional: Piper ljspeech; swap to cori or Kitten by changing one line after the phone rating) and downloaded at build time from sherpa-onnx's release with a SHA-256 check; espeak-ng-data trimmed to en/hi/bn (ADR-014).
- **Phone's own TTS** (`SystemSpeechEngine`): `synthesizeToFile` into the cache, chunked by `getMaxSpeechInputLength()` at sentence/clause/space boundaries; only offline, installed voices; `bestVoice(lang)` says NOT_INSTALLED or NETWORK_ONLY per language when the voice pack is missing. Entry points: `SpeechEngines.bundled(context)` and `SpeechEngines.system(context)`.
- Tests: 44 JVM tests (chunker table, WAV reader, PCM conversion, manifest parsing, asset install incl. a killed copy, both engines over fakes: voice choice, missing packs, chunk join, sample-rate mismatch, errors, cancellation, release during a render). Device tests (emulator job, `:speech:connectedDebugAndroidTest`): the bundled voice renders real speech from the APK, a cancelled render leaves it usable, the system engine renders or reports a typed reason. Build task checked locally: Piper and Kitten unpack and speak in desktop sherpa-onnx; a wrong pin fails the build.
- APK grows by ~92 MB (model, espeak data, sherpa-onnx native libraries). No new libraries.

**Real-device checks (batched into the overnight run, Moto Edge 50 Fusion):** covered by P1-04's playback run: the first sentence starts within ~2 s of Play on a fresh install (model load + espeak copy), and a Hindi book with no Hindi voice pack installed shows the "download it in Text-to-speech output" message.

## P1-07 — Diagnostics (2026-10-15)
- **Settings → Share logs:** a gear on the home screen opens Settings; "Share logs" zips a `summary.txt` (app version, phone, Android version, unfinished read, last 10 process exits) and the rolling log files into `cacheDir/shared-logs/` and opens the share sheet through a FileProvider limited to that folder. One zip, because every chat and mail app takes a single attachment and text logs compress about tenfold. The log queue is flushed first so the newest lines are included. No PDF text or book titles go into the log or the summary.
- **Process deaths are logged:** at every process start (background thread) Audora reads Android's `ApplicationExitInfo` history and writes each exit not yet logged: kind (SIGNALED, LOW_MEMORY, CRASH, CRASH_NATIVE, ANR, USER_REQUESTED, FREEZER…), signal/exit status, importance (e.g. `FOREGROUND_SERVICE(125)`, the OEM-kill signature), memory and Android's description. Abnormal kinds are warnings. A cursor in `filesDir/diagnostics/state.properties` makes each exit appear once.
- **Unfinished-session detection:** `ReadingSessionTracker` (`:core`) keeps an "audio is playing" marker on disk (atomic write + fsync). A marker found by a new process means the old one died mid-read: the log gets "Reading stopped unexpectedly: book=… page=…; cause: <exit>" and the app shows "Reading stopped unexpectedly — resume?". Paused sessions are not markers, so Android reclaiming a paused app never triggers the prompt.
- **Hooks for later tickets:** P1-04's playback service must call `onPlaybackActive(bookId, page)` on play and page change and `onPlaybackInactive()` on pause, stop, end of book and sleep timer. P1-06 makes "Resume" start playback at the `ResumeAnchor` (`TODO(P1-06)` in `DiagnosticsController`); until then Resume only closes the prompt.
- **Debug builds only:** Settings has "Simulate a reading session", which sets the marker without audio so the prompt and the exit logging can be checked on a phone before P1-04.
- Settings is a second screen switched by state and closed with back; P1-01 replaces it with real navigation. No new dependencies.
- Tests: JVM tests for the state file (round trip, corrupt file, stale temp file, unwritable folder), the tracker (dies while playing, paused, page change, repeated deaths, resolve), startup exit logging (once per exit, levels, cause selection), the zip writer and the summary; an app unit test for the Android reason/importance mapping.
