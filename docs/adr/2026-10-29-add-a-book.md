# ADR 2026-10-29-add-a-book: Add book opens one sheet with every way a book comes in

**Status:** Accepted (2026-10-29). Second findability PR from the maintainer-approved audit. Follows the layout
rule: sheets for quick choices; the top bar's ⋮ only for options about the screen.

## Context

The library's big Add book button opened only the file picker. Six other ways in sat in the ⋮ menu among backup,
sync, quiz and stats: Point and read, pictures from the gallery, copied text, a web page, free book catalogues and
watched folders. Most listeners never open ⋮, so they never found them.

## Decision

- **Add book (the button, and the empty library's button) opens "Add a book":** Choose a file first, then the six
  tools in their enum order. Each row has an icon, its name and one line on what it reads ("One article, without menus
  or ads"); the long hint stays behind its info button.
- **`LibraryAction.place`** (`MENU`, `ADD_SHEET`, `BUTTON`) replaces the `inMenu` flag, which stays as a derived
  property. The six ways in are `ADD_SHEET` and leave ⋮.
- **A row closes the sheet before it runs,** so the camera, a picker or the catalogues' own sheet never opens over it.
- **Search** still finds the six, now under "Library › Add book".
- The first-run screen's own Add button still opens the file picker directly: it is one step of a guided start.

## Consequences

- Six more icons (Material, Apache-2.0), under 2 KB together. The sheet is built only when it opens.
- ⋮ is shorter (sync, backup, quiz, stats, Make it yours) until the re-homing PR moves those to the drawer and
  Settings.
- Adding a book from a file takes one more tap (Add book, then Choose a file). Accepted: every other way in becomes one
  tap from the same button.
