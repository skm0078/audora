# ADR 2026-10-26-web-books: web pages and free book catalogues, fetched only on the listener's tap

**Status:** Accepted (2026-10-26). Amends D1 and AGENTS.md "No network except model downloads": the app may now also
fetch what the listener taps. Tickets CF-12 (web article from a link) and CF-15 (OPDS catalogues) of the competitor
coverage study, moved into the final Kotlin batch by the maintainer on 2026-10-26.

## Context
Every competitor reads a web article from its link, and most offer a free public-domain library. ListenLock answered
a shared link with "select the text and share that", and had no way to find a free book. Online and server features
stay in the Flutter Pro app; a download the listener taps, like a voice download, is allowed in the Kotlin app.

## Decision
1. **Only on a tap.** A web page is fetched when the listener taps Read (Library ⋮ > Read a web page, or the prompt
   for a link shared to ListenLock, which names the site first). A catalogue page is fetched when it is opened, a
   book when Download is tapped. Nothing runs in the background, ahead of time, or on a schedule; nothing is cached.
2. **HTTPS only, nothing about the listener.** `WebFetcher` (HttpURLConnection, no HTTP library) sends the address, a
   browser-style name with "ListenLock", and the accepted types. No cookies, no account. Redirects only https to
   https. Size caps: 8 MB for a page, 200 MB for a book (`WebBooksConfig`). An address with `user:password@` is
   refused. Logs name the host, never the address.
3. **Article extraction with Readability4J 1.0.8** (Apache-2.0, a port of Firefox Reader View) on **jsoup 1.23.2**
   (MIT; pinned above the 1.11 Readability4J asks for, for its fixes; same API, checked by the unit tests). The kept
   block is re-read one paragraph per block element, so headings and paragraphs keep their pauses. The article becomes
   shared text (a `.txt` text book); the downloaded page is deleted. A link straight to a PDF, EPUB or text file is
   kept as that book instead. SLF4J API comes with Readability4J and logs nothing (no binding).
4. **OPDS 1.x (Atom) catalogues**, parsed with jsoup's XML parser (no external entities). Built in: Project Gutenberg
   (no account). Standard Ebooks is not built in: its OPDS feeds need a paid Patrons Circle login. The listener can add
   any https OPDS address (checked by reading it first; at most 20). Sections open as pages; a book shows Download
   when it has a free (`acquisition`, `acquisition/open-access`) link in a format ListenLock reads, best first: EPUB,
   PDF, text, DOCX, ODT, RTF. Search uses the feed's Atom template or its OpenSearch description. "More" follows
   `rel="next"`.
5. **Books land in the library's own copies folder** (`SharedPdfCopies.newCopy`), are added and opened like a shared
   file, and are deleted with their book. One download at a time; Cancel deletes what was written.

## Consequences
- The privacy policy, the in-app privacy statement and the README say what is fetched and from where.
- New libraries in the APK: Readability4J, jsoup, SLF4J API (about 0.7 MB before R8). Listed on Voices & licences.
- Plain http catalogues (a Calibre server at home) are refused; https only. OPDS 2 (JSON) catalogues are not read.
- Pages built entirely by scripts have no article in their HTML and get "no article on that page".
- Not doing: logins for paid catalogues, cover pictures in the list (no image library), background updates.
