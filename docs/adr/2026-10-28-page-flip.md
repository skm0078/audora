# ADR 2026-10-28-page-flip: turn PDF pages by swiping, with the pages beside drawn ahead

**Status:** Accepted (2026-10-28). Third of the features the maintainer moved ahead of v0.1.0 (share cards, video
export, page-flip reader), part 3a: PDF and other drawn pages. Part 3b (EPUB and text books laid out as pages) follows.

## Context

The reader turned pages only with the arrows in the page bar, the page picker or the scrubber. Every e-reader lets
you swipe or tap the page's edge, and a page turned by hand should land on a finished page, not a spinner. Pages
are drawn by PDFium one at a time behind one lock (the page view and the scrubber share it). Each page bitmap is
about 6.6 MB at a phone's width (1080 px, A4), up to 16 MB at the 4 MP cap when zoomed in.

## Decision

- **Swipe** (`ui/reader/flip/PageFlip`): a sideways drag moves the page with the finger and slides the neighbour in
  beside it. Let go past a quarter of the width, or with a quick flick, and it slides the rest of the way; a flick
  back, or a short slow nudge, settles it back. Past the first or last page it gives a little (30 %) and settles back.
  The drag is read after the page's own pinch and vertical scroll, so neither is taken for a turn; zoomed in, a
  sideways drag pans the page as before and never turns it.
- **Edge taps**: a tap in the outer fifth of the page, away from any sentence, turns the page (not while zoomed in).
  A tap on a sentence still reads from it, as before.
- **Drawn ahead** (`PageNeighbours`, `ReaderModel.drawAhead`): once the shown page is on screen, the next page and
  then the one before are drawn in the background behind the same lock (the shown page and the scrubber always go
  first), and their sentences read with `pageIfReady`, which never starts OCR for a page ahead. A turn to one shows
  it at once. At most three pages are held (the shown one and one each side); a new width (rotation, zoom) lets the
  old ones go; zoomed in or in the text view nothing is drawn ahead.
- **"Read from here"** beside "Back to page N, where reading is": after turning away by hand, reading carries on from
  the shown page's first sentence in one tap.
- **TalkBack**: unchanged and already right: TalkBack's own swipes are its gestures, the page bar's arrows turn the
  page, and the page number is announced when it changes while not reading aloud.
- **Settings** (`PageFlipConfig` in `ReaderConfig.flip`): `drawNext`, `drawPrevious` (the lighter "next page only"
  option), edge share, turn share, fling speed, edge give.

## Cost (measured by size, flagged to the maintainer)

- **Memory:** two extra page bitmaps while a PDF page is shown: about 13 MB at phone width (6.6 MB each), 0 in the
  text view or zoomed in. Lighter option, one setting away: draw only the next page (about 6.6 MB, swipes back show
  the page a moment later).
- **CPU:** one extra page render each way after each turn (the same work the turn would have done, done earlier),
  behind the shown page. No OCR is ever started ahead.
- **APK:** about 10 KB of code, no new dependency. **Cold start:** none (nothing runs until a page is shown).

## Not in this change (follow-ups, not dropped)

- **Curl animation** (page curl, API 33+ shader): Slide is the default and the only animation here; Curl comes as a
  choice in a follow-up.
- **Volume keys turn pages while paused** (a setting): follow-up, as it needs key handling in the main activity.
- **EPUB and text books as pages** (part 3b): next PR.

## Alternatives considered

- **`HorizontalPager`** with one page view per page: composes and draws a full page view per neighbour (scroll
  states, highlight layers, hit testing), and fights the page's own pinch and pan. Drawing the neighbours as plain
  images while a finger moves is lighter and keeps one interactive page.
- **No drawing ahead**: no memory cost, but every swipe lands on a spinner for a render (100-300 ms on a mid phone).

## Consequences

- `ReaderState.nearbyPages` holds the drawn-ahead images; `ReaderActions.onPageZoomed` tells the model when the page
  is zoomed. Both have defaults, so other screens and tests are untouched.
- Render counts in tests now include pages drawn ahead; tests that count renders filter by page.
